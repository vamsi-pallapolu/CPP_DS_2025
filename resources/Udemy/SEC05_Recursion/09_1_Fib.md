# Fibonacci — Three Implementations (Iterative, Recursive, Memoised)

Source: `SEC05_Recursion/9_1_Fib.cpp`

## Why three versions?

Fibonacci is the canonical example for **why recursion needs memoisation**. Naïve recursion recomputes the same sub-problems exponentially many times; memoisation caches them and drops the cost to linear.

## 1. Iterative — O(n) time, O(1) space

```cpp
int fib(int n)
{
    int t0 = 0, t1 = 1, s = 0;
    if (n <= 1)
        return n;
    for (int i = 2; i <= n; i++)
    {
        s  = t0 + t1;
        t0 = t1;
        t1 = s;
    }
    return s;
}
```

- Baseline for correctness and speed. Use this in production.

## 2. Naïve recursion — O(φⁿ) time

```cpp
int rfib(int n)
{
    if (n <= 1)
        return n;
    return rfib(n - 2) + rfib(n - 1);
}
```

- Direct translation of the recurrence.
- **Every non-leaf call spawns two more** — the call tree is roughly a binary tree of depth `n`, so the number of calls is ≈ `φⁿ` where `φ ≈ 1.618`.
- `rfib(40)` takes seconds; `rfib(50)` takes minutes.

### Why is it so slow?

```
rfib(5)
├── rfib(4)
│   ├── rfib(3)
│   │   ├── rfib(2)
│   │   │   ├── rfib(1)
│   │   │   └── rfib(0)
│   │   └── rfib(1)
│   └── rfib(2)         <- recomputed
│       ├── rfib(1)
│       └── rfib(0)
└── rfib(3)             <- recomputed entirely
    ├── rfib(2)         <- recomputed AGAIN
    └── ...
```

`rfib(2)` is computed 3 times, `rfib(1)` 5 times, and so on.

## 3. Memoised recursion — O(n) time, O(n) space

```cpp
int F[10];   // global cache, must be initialised to -1

int mfib(int n)
{
    if (n <= 1)
        return n;
    if (F[n - 2] == -1)
        F[n - 2] = mfib(n - 2);
    if (F[n - 1] == -1)
        F[n - 1] = mfib(n - 1);
    return F[n - 2] + F[n - 1];
}

// caller must do:
for (int i = 0; i < 10; i++) F[i] = -1;
```

- Cache lookup: if `F[k]` is already computed (not `-1`), skip the recursion.
- Each `F[k]` is computed at most once → O(n) recursive calls total.
- Space cost: an array of size `n + 1`.

## Complexity summary

| Version | Time | Space | Notes |
|---|---|---|---|
| Iterative `fib` | O(n) | O(1) | Best in practice |
| Naïve `rfib` | O(φⁿ) | O(n) stack | Never use for `n > 30` |
| Memoised `mfib` | O(n) | O(n) heap + O(n) stack | Same time as iterative, more overhead |

## Gotchas

- The memo array size (`F[10]`) caps `n`; the caller must ensure `n < 10` or resize.
- Global mutable state (`F[]`) is a code smell — in real code use `std::vector` passed as a parameter, or a `std::unordered_map` keyed by `n`.
- The sentinel `-1` only works because Fibonacci values are non-negative. For general memoisation, use `std::optional<T>` or a "seen" bitmap.
- Memoisation trades stack recursion for cache lookup — for large `n` you may still blow the recursion stack even though you avoid recomputation. Use **bottom-up DP** (fill `F[0]..F[n]` iteratively) to eliminate recursion entirely.
